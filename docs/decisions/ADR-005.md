# ADR-005: Experience update strategy

## Status

Accepted

## Context

Updating experience skills purely from `SkillId`s is tricky because there's no direct way to difference between a delete update and an add update for an experience skill.

## Decision

Experience skills will be synced from the update DTO to the domain by a simple comparison. If an experience skill does not exist on the DTO, then that should be the case in the domain model, however if it does on the DTO then that should again be the case in the domain model as well.

## Alternatives

Update the update DTO to include an action flag that signals either a deletion or an addition of an experience skill. This clutters the update DTO unnecessarily.

## Consequences

This will only work if frontend correctly parses the `SkillId` structure in the update payload, which adds to the list of ways this can possibly fail.
