# ADR-003

## Status

Accepted

## Context

The API currently implements full CRUD operations on the profile controller. By design, all `GET` operations are public, and the rest are gated behind JWT authentication. For a single user API, this is an efficient way to add a security later with adding unnecessary complexity. Identity authentication is overkill for this project, however it is something I can consider on a multi-user project.

## Decision

The API is gated by JWT authentication instead Identity-based authentication like AAD.

## Alternatives

Identity-based authentication Microsoft's Entra ID offer a security later that supports multi-user projects. A better alternative that would unfortunately add unnecessary complexity to a simple single user API.

## Consequences

Transferring to a multi-user setup would require architectural changes, an acceptable consequence.
