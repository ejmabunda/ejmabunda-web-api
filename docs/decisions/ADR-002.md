# ADR-002: Refresh token audit trail

## Status

Accepted

## Context

Sessions store hashed refresh tokens which are rotated per refresh by replacing the current token in the session. This removes audit trails in case of refresh token theft, and prohibits session revocation.

## Decision

A dedicated refresh token table keeps records of previous token usage and will allow the system to detect replay per session and ultimately revoke affected sessions entirely.

## Alternatives

1. Add a `PreviousRefreshToken` field on a `Session` to detect immediate replay. This is not useful in cases where a token that dates two or more rotations back is replayed.

## Consequences

In addition to the `Session` table, we now need to schedule cleanup for the `RefreshToken` table periodically, and manage abondoned sessions. At the current scale, this wouldn't cause database storage issues.
