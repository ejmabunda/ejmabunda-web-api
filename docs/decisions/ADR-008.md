# ADR-008: Replace keep-alive workflow with Azure Logic App

## Status

Accepted, Supersedes [ADR-007](ADR-007.md)

## Context

`keep-alive` workflow's flaw is actually worse than GitHub suggests, cron jobs can sit in a queue for hours - 4 - 5 hours in my case - and occasionally dropped from the queue entirely. This defeats the purpose of the workflow. Only 3 ran on schedule yesterday and they are hours apart.

## Decision

Setup an Azure Logic App to ping the api every 15 minutes. This is free for the first 4000 executions per month per subscription.

## Alternatives

External/third-party tools like cron-job.org and UptimeRobot are free, and fire on time. These are rejected in favor of Azure native tools since building on Azure is the goal of this project.

## Consequences

1. This is a new concept, so there's a learning curve and more room to make mistakes. An acceptable consequence that supports learning.
2. The 4000-action free grant is shared across every Logic App in the subscription, not per app. Each run is a Recurrence trigger plus an HTTP action (2 actions), so a 15-minute cadence is roughly 5.8k actions/month — slightly over the grant, i.e. a few cents rather than exactly free. Dropping to a 30-minute cadence stays within the grant if strict $0 is needed.
3. The Logic App lives outside CI/CD. It's portal-managed, with `infrastructure/logicapp_keepalive.json` as a hand-exported snapshot, so it's drift-prone — portal edits aren't tracked in git.
4. If the App Service hostname changes, the ping URL in the Logic App must be updated by hand.
